# 0001. Telegram MVP, затем веб на общем backend

## Контекст

Нужно быстро получить работающий прототип, проверить сценарии и только потом
делать полноценный веб-интерфейс. Нельзя дублировать бизнес-логику между
каналами.

Ранее в `PLAN.md` предлагался OpenClaw как основа. Для текущей задачи это
лишняя зависимость: нужен свой backend и предсказуемый веб-этап.

## Решение

1. MVP — Telegram-бот на aiogram.
2. Бот — тонкий клиент к FastAPI: `/chat`, `/voice`, `/events`, `/search`.
3. Backend и PostgreSQL — общие для Telegram и веба.
4. После приёмки Telegram MVP делаем React-фронтенд на том же API.
5. OpenClaw не используем.

## Последствия

Плюсы:

- быстрый MVP в Telegram без вёрстки;
- один backend и одна доменная логика;
- веб добавляется без переписывания;
- проще тестировать и деплоить.

Минусы:

- нужен свой scheduler напоминаний;
- Telegram-бот и frontend надо поддерживать отдельно;
- API-контракт нужно фиксировать до кода.

## Границы

- Сначала 4 обязательных сценария в Telegram.
- Веб начинаем только после зелёной приёмки MVP.
- OpenClaw-код и конфиги в проекте не используются.
